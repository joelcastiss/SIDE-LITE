# Protección de ingresos y configuración perimetral

En la API se conservan los límites atómicos por identidad y por código compartido. El contador por código limita simultáneamente solicitudes de alta y recuperación de todas las identidades; no pretende identificar IP ni ser una solución contra ataques distribuidos. Los accesos cruzados siguen condicionados a identidad Auth, membresía y capacidad aleatoria; los fallos del almacén deniegan la operación. El presupuesto por código puede bloquear una sala bajo ataque; supervisarlo y ajustar ventanas con pruebas de concurrencia antes de habilitar aulas reales. Los límites por sala no sustituyen a un control de perímetro.

Supabase Auth aplica de forma administrada límites por IP al alta anónima y a autenticación (ver https://supabase.com/docs/guides/auth/rate-limits). No se utiliza `X-Forwarded-For`, `CF-Connecting-IP` u otra cabecera cliente en la función: no se ha verificado un contrato que garantice su reemplazo por el proxy de entrada. No habilitar `Sb-Forwarded-For` salvo que una arquitectura proxy verificada use una clave secreta en servidor y elimine cualquier cabecera de cliente.

Configurar límites de Auth adecuados para aulas con redes compartidas. El script `scripts/verify-supabase-auth-guard.mjs` comprueba los límites de identidades anónimas y la configuración de proxy sin mostrar secretos. Mantener los controles de identidad, autorización y límites de ingreso de la API.
